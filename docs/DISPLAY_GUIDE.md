# 现场比赛大屏展板使用指南

版本：1.1.0 · 两个赛项共用展板 · TCP 协议仍为 v1

## 1. 交付内容与使用边界

这是接入原有 TCP 裁判服务端的只读网页，不是单纯效果图。原有裁判窗口继续负责场次、箱型、预期答案、开始/取消测试和证据导出。网页只接收明确允许公开的状态，不提供裁判操作接口。

`preview_display.html` 是可以单独打开的界面预览，内置模拟数据，右上角和底部明确标记“演示”。它不接相机、不连 TCP、不写比赛数据库。**正式比赛必须打开运行中服务端的网页地址，不能把预览页面当作现场数据。**

本版展示结果和通信状态，不展示实时相机图像、检测框或缺陷位置，也不生成正式成绩、准确率、排行榜。原有 TCP 契约没有定义实时图片流；页面没有用示意图冒充相机画面。

## 2. 一台 Windows 电脑连接大屏

完整解压工具包，双击 `start_server.cmd`。原有 Python/Tk 运行要求不变，无需安装 Node.js、Flask 或任何前端依赖。

程序会同时启动裁判窗口和本机只读网页服务。网页默认地址：

```text
http://127.0.0.1:9080/
```

点击裁判窗口右上角 **“打开现场大屏 ↗”**。网页未开始比赛时显示“待开赛”，不会生成模拟数据。继续按原有方法建立场次、启动 TCP 监听、连接参赛客户端并开始测试，网页自动更新。

大屏投放建议：接好显示设备后按 `Win + P`，选择 **“扩展”**。裁判窗口留在笔记本/主显示器，只有浏览器窗口拖到大屏。不要使用“复制/镜像”把裁判接入码、预设答案、样件名称和内部日志一起投放给观众。

网页移动鼠标会显示右下角工具栏。点击“全屏”或按 `F` 切换全屏，`Esc` 可退出浏览器全屏；浏览器未授权页面全屏时，可使用浏览器自身的全屏功能。全屏需要一次用户操作，程序不会声称能无条件绕过浏览器限制。

工具栏在不操作后自动收起。支持“明亮模式”和“深色模式”，主题优先保存在本浏览器；浏览器禁止本地存储时仍可切换，只是不保证下次记住。

## 3. 使用另一台电脑连接大屏

在裁判电脑的解压目录打开 PowerShell，运行：

```powershell
.\start_server.cmd --display-host 0.0.0.0 --display-port 9080
```

例如裁判电脑的比赛网卡地址为 `192.168.1.10`，大屏电脑打开：

```text
http://192.168.1.10:9080/
```

上述 IP 仅为示例，必须改成裁判电脑实际地址。不要在大屏电脑使用 `127.0.0.1` 指向裁判电脑；`0.0.0.0` 也不是浏览器的访问目的地址。

**TCP 检测端口和网页端口彼此独立：**

| 用途 | 默认端口 | 设置位置 |
|---|---:|---|
| 参赛视觉软件连接、上报检测结果 | 9000/TCP | 原有裁判窗口“网络监听” |
| 大屏浏览器查看公共展板 | 9080/HTTP | 启动参数 `--display-port` |

开放网页监听不会自动开放 TCP 的局域网监听。参赛电脑也在另一台机器时，仍需在裁判窗口把 TCP 监听 IP 设为比赛网卡地址或 `0.0.0.0`。

Windows 防火墙由现场管理员按比赛网卡、网络配置文件及大屏电脑 IP 放行所需端口。不要关闭整个防火墙，不要把网页或 TCP 端口映射到公网。默认仅监听 `127.0.0.1` 是有意设置的。

仅需更换网页端口：

```powershell
.\start_server.cmd --display-port 9081
```

仅运行原有裁判端、不运行网页：

```powershell
.\start_server.cmd --no-display
```

网页端口被占用时，裁判窗口底部提示原因；TCP 裁判功能不因此停止。更换网页端口后重启，已打开的浏览器需要访问新地址。

## 4. 修改比赛标题

裁判窗口右上角 **“展板设置”** 可编辑标题和副标题。点击“保存并更新展板”后，连接中的展板同步更新，设置写入数据目录的 `settings.json`。

标题最多 28 个字符、副标题最多 56 个字符。默认标题为“工业视觉技能竞赛”。队伍名称和赛项来自当前已创建的场次，不从尚未应用的输入框读取；切换赛项须在裁判端新建场次。特别长的队名按界面宽度省略显示，鼠标悬停可查看完整文本。

观众网页无修改标题、开始比赛、修改预期、导出数据的接口；这些功能仅在裁判电脑的桌面程序中操作。

## 5. 显示内容与统计口径

| 展示区域 | 含义 |
|---|---|
| 当前参赛队伍、竞赛项目、当前轮次 | 当前场次和最新创建轮次；不是最后到达报文所指向的轮次 |
| OK / NG | 参赛视觉软件上报的产品判定；不是裁判的正确性结论 |
| 检测中、已超时、已取消、已中断 | 与产品判定分开的轮次状态，不会被自动换成 NG |
| 本场测试轮次 | 当前场次已经创建的轮次数，包含取消/中断/等待的轮次 |
| 已接收结果 | 已收到最终结果的轮次数，包含迟到结果；迟到另行标注 |
| 客户端输出 OK / NG | 当前场次结果分布；NG 数不是扣分数 |
| 最近轮次 | 按轮次编号倒序，最多展示最近 6 轮 |
| 观测耗时 | 服务端开始本轮至完整结果进入服务端处理的耗时；不是纯推理耗时 |
| 耗时趋势 | 最近创建的 20 轮中，已收到结果并有耗时记录的轮次；不补造空缺点 |

“10 轮”进度仅提示评分表中连续测试的**数量参考**。已经创建 10 轮不等于有 10 轮有效连续检测，也不等于稳定性合格或获得对应分数，须由裁判审核。

未公开裁判预期、样件类别、正确性核对结果、裁判备注、箱型/型号配置细节、接入码、客户端地址、原始通信日志和数据库文件。公共数据通过服务端白名单构造，不是先发完整数据再用 CSS 隐藏。

## 6. 断线和刷新

网页约每 0.5 秒拉取一次缓存快照；后端约每 0.35 秒发布一次公共快照。网络、系统负载和浏览器调度会带来显示延迟。最终耗时和结果以服务端保存的证据为准，不以网页动画或屏幕录制帧数计算。

网页显示两种独立的连接状态：参赛端 TCP 连接状态，以及网页到展板服务的数据新鲜度。参赛端掉线会显示“客户端未连接”，已完成的最近一轮仍明确标注为历史最近结果。

网页请求失败、或发布快照约 2.5 秒没有更新时，主要判定区切换为“已离线”，横幅提示暂停更新。下方旧统计和旧记录变暗，表示只保留上次记录；不会继续把旧 OK/NG 当作实时结果，也不会自动显示演示数据。恢复后自动重新显示实时状态。

一条旧轮次的迟到报文只更新那一轮的记录，不覆盖更新轮次的主要判定区。服务端切换队伍/赛项后，网页只显示新场次，旧场次留在裁判端历史记录中。

## 7. 画面尺寸

按 1920×1080 设计，整体等比例适配浏览器可用区域，文字和状态图标为网页/SVG 渲染。已在测试浏览器中检查 1366×768、1920×1080、3840×2160 和 1280×1024；这些尺寸下展板与面板内容没有溢出。非 16:9 画面可能出现留边，这是为了不拉伸布局。

建议现场按大屏实际分辨率全屏展示，并站到观众最远位置检查文字大小。真实 LED 拼接屏的缩放、边缘裁切、亮度、色彩和 Windows 多显示器缩放尚需现场验收。程序不会自动修改 Windows 的显示分辨率或电源策略。

原交付压缩包的示例截图在 `docs/screenshots/`，均为真实网页渲染截图、数据明确标记为演示。Git 仓库不跟踪自动生成的截图；可运行测试脚本重新生成，或打开 `preview_display.html` 预览。

## 8. 升级与打包

本次未改变 TCP v1 报文，也未改变数据库 schema。旧客户端不需要为了大屏页面修改检测报文。

从 v1.0 升级时先正常关闭旧程序并备份整个旧数据目录。新版本另解压到一个目录；使用 `start_server.cmd` 的用户可以把旧 `data` 文件夹完整复制到新版根目录后启动。不要同时打开两个程序使用同一个数据库，不要运行中仅复制 sqlite3 主文件而遗漏 WAL 文件。

`build_exe.cmd` 已加入 `competition/web` 静态资源打包参数。需要在 Windows 上构建并复制完整输出目录。此次未生成、未验证 Windows EXE。

## 9. 可修改的文件

```text
competition/web/index.html   页面结构
competition/web/style.css    深色/明亮主题、版式、字号
competition/web/app.js       展示逻辑、状态、图表、全屏与演示
competition/display.py       公共快照白名单、缓存、只读 HTTP
competition/gui.py           桌面大屏入口与标题设置
preview_display.html         独立演示页（生成产物）
tools/build_preview.py       修改资源后重新生成独立演示页
```

前端没有外部 CDN、远程字体、统计脚本或在线图片依赖。无需 npm 构建。发布时不包含字体文件。

后端使用标准库 `http.server` 构建嵌入式只读服务，有静态资源白名单、并发上限、请求超时、无目录浏览和不缓存响应等限制，但这不是公开互联网 Web 服务的安全加固方案。HTTP 无 TLS，局域网模式无观众身份认证，公开队伍名和比赛状态对能够连接该端口的人可见。
