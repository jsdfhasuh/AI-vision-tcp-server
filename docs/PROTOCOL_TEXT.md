# 四工位 TCP 简单文本协议

本次扩展在原四工位监听端口接收纯文本，推荐参赛端使用。标准清单JSON导入、两个工位分别选定标准、LOGO/火焰独立结果、页面和数据库仍沿用原流程。没有新增比赛场次、轮次、得分、型号文字OCR或目标下发。

## 可以直接发送的报文

电机螺钉：`screw,工位号,选手工号,螺钉数量,end`

```text
screw,1,D70516,4,end
screw,2,D70517,3,end
```

包装箱：`packaging,工位号,选手工号,完整条码,LOGO结果,火焰标识结果,end`

```text
packaging,1,D70516,001234-AbC,OK,NG,end
packaging,2,D70517,005678-DeF,NG,OK,end
```

每行是独立报文，发到对应工位的连接。工位号1/2；工号仅标明操作者，不决定标准、不需要注册。螺钉只传数量、不传OK/NG；数量是0～2147483647的非负十进制整数（最多10位），不接受负号、加号、小数、科学记数或数字以外内容。

LOGO、火焰均必填，只接受大写OK或NG，顺序固定，不细分原因。条码未读到时保留空字段：

```text
packaging,1,D70516,,OK,NG,end
```

条码已读到时与该工位当前选定标准精确比较。前导零、大小写、首尾空格与Unicode均原样保留；不截取、不数值化、不归一化。未导入标准显示未配置，清单存在但工位未选择显示未选择，空条码显示未读取，都不会自动补成NG。换箱时先等上一件结果入库再切换标准，首次迟到数据只能按入库时的标准比较。

## 字节、分帧和连续接收

使用UTF-8，无BOM；字段用英文逗号，项目名和末尾`end`为小写。末尾实际发送的是逗号加三个字母，即`,end`，不需要换行或空字符。也容忍帧间可选的LF/CRLF，字段内不能出现控制字符或换行。不要发送字面量的`\n`。

字段数固定：螺钉5段、包装箱7段（均包含项目名和末尾end）。工号最长64字符、不得有首尾空白；条码最长512字符；两者均不能包含英文逗号，无引号/反斜杠转义语法。如果真实条码含逗号，此简单格式不能承载，需使用已有JSON v2兼容路径，不能删除条码中的逗号冒充原值。

接收器缓存并处理拆包、粘包以及拆开的UTF-8字节和结束标志。**按固定字段位置识别end，不是找到任意end子串就截断。** 条码是`end`或`ABCend001`均合法，例如：

```text
packaging,1,D70516,end,OK,NG,end
```

同一工位可在一个TCP连接连续发送：

```text
screw,1,D70516,4,endscrew,1,D70516,3,end
```

这会保存两条记录、回复两次`ACK,end`。回执同样可能拆包、粘包，客户端必须缓存解析，不能将一次recv等同于一次回执。简易客户端建议每次发一条、等回执后再发下一条。

最大帧16KiB，文本帧包含end、不包含可选外部换行；不完整帧最多等待5秒，每连接每秒最多100帧。明确分帧错误（未知项目前缀、字段过多、错误结束标记）返回错误并断开，避免猜测边界后写入错误数据。有效边界下的字段值错误会返回错误，累计5次关闭；缺少完整结束标记的报文超时或超长后断开，不记录为检测NG。

## 回执和连接

| 情况 | 服务端回复 |
|---|---|
| 检测已成功提交到数据库 | `ACK,end` |
| 可选hello连接标识成功 | `HELLO,end` |
| 心跳 | `PONG,end` |
| 格式或字段错误 | `ERR,FORMAT,end` |
| 工位已有另一个活动连接 | `ERR,STATION_BUSY,end` |
| 同一连接试图更换项目/工位 | `ERR,STATION_MISMATCH,end` |
| 未标识工位就发心跳 | `ERR,IDENTIFY_FIRST,end` |
| 完整报文超长或发送频率超限 | `ERR,LIMIT,end` |

ACK只代表保存，不反馈条码匹配结论、标准条码、标准编号或得分。存储故障停止接收、不假报成功。原始文本收发保存在TCP通信日志；数据库内部仍使用规范化结构和服务器生成的记录编号，不要求选手发送这些字段。

连接后5秒内可直接发送第一条完整结果，或先发送：

```text
hello,screw,1,end
```

包装箱工位可用`hello,packaging,1,end`。hello不生成检测记录、不设置工号；工号跟随result更新。空闲时每5秒发送`ping,end`；30秒无有效消息会断开。四工位各一个活动连接，项目+工位不能在同一连接内切换；工号可变化。连接断开不会删除历史，重连后等待新数据。

**纯文本没有检测编号：每次有效接收都是一条新记录。** 同样数量或条码可能本来就是连续检测，不进行按内容去重。没有ACK时结果可能已保存，必须先核对，不能盲目重传。示例客户端不自动重试。未来需要有编号的可靠重试时，必须另行明确字段，不能把现有内部UUID当成客户端传来的检测ID。

## 兼容、更新与联调

更新后仍用`python web_server.py`启动，不加`--legacy-v1`。停止旧进程、拉取代码后重启；不必重建管理员、导入标准或数据库。本次不升级数据库schema，也不重判历史。

`station_client.py`默认发送文本，参数不变：

```powershell
python station_client.py --project screw --station 1 --worker-id D70516 --count 4
python station_client.py --project packaging --station 1 --worker-id D70516 --barcode "001234-AbC" --logo OK --flame NG
```

跨电脑使用时加`--host 服务器局域网IP --port 9000`，确保监听地址与隔离网络防火墙允许。9000是默认TCP端口，9080是网页端口；不能把文本发送到网页HTTP端口。示例程序只发一次后退出，页面随后显示断开但记录保留。

已有JSON v2客户端保留兼容，首帧为JSON对象的连接继续按LF分帧及按msg_id去重；同一连接不能混用两种格式。示例CLI加`--json-v2`显式使用原格式；原Python函数`send_result()`继续发送JSON，新`send_text_result()`发送纯文本。JSON兼容路径的重试语义不适用于文本报文。

两种TCP格式都无密码认证/加密，仅用于可信隔离网络；不要直接开放到公网。Web鉴权和JSON标准导入仍保留，并不因TCP改成文本而取消。
