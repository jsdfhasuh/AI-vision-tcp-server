# 正式上场前验收清单

这份清单供裁判、开发人员和现场操作员共同确认；自动化协议测试通过不能替代实物及Windows真机验收。

## 1. 先冻结比赛口径

| 事项 | 待确认内容 |
|---|---|
| 协议 | 全部参赛端使用本协议v1，还是另有统一格式；不能混用裸OK/NG |
| 超时 | 是否启用；正式毫秒数；服务端开始轮次到完整结果处理的计时口径是否被接受 |
| 触发 | 默认arm仅布置轮次，或统一trigger启动检测；明确相机真正的触发来源 |
| 箱型 | box_type取值、对应产品型号、标签类型和本地映射表；空字符串的约定 |
| 重传 | 同msg_id同内容重传与新msg_id重复，分别如何影响评分 |
| 场次 | 单队单连接；裁判是否按物理样件逐轮开始记录 |
| 总分 | 包装箱截图中的分值不一致处以何种正式版本为准 |
| 记录 | 记录保留时长、交接人员、接入码及原始日志的保密范围 |

## 2. Windows程序验收

在目标比赛电脑上源码启动成功、关窗正常退出、再次启动能查看历史；中文显示及100%/125%/150%DPI缩放可用；窗口最大化后控件、结果表和导出入口完整；解压目录及数据目录有写入权限；重复启动同一数据目录被阻止；选择另一个目录不会污染旧数据。

需要EXE时，在Windows执行打包脚本，复制完整输出文件夹到另一台未装项目依赖的Windows机器验证。检查EXE实际数据目录与备份方式。未做这一步，不标记“EXE验收完成”。

## 3. 网络及身份验收

本机模拟收发正常；不同电脑在比赛网络正常连接；错误接入码/客户端ID被拒绝；第二个客户端不能顶掉当前参赛端；切换场次后旧码失效；正确目标版本确认前不能开始；目标改动后必须重新确认；软件推理繁忙时心跳仍能持续。

服务端设为具体网卡IP或0.0.0.0时，参赛端使用实际裁判IP。检查防火墙仅放行比赛需要的范围，不开放公网，不关闭整个防火墙。

## 4. 包装箱赛项实物验证

| 样件/情况 | 主要核对 |
|---|---|
| 合格品 | 两路视觉均正常，客户端最终OK；裁判端实际OK、核对一致 |
| 正面LOGO破损 | 客户端自行判NG，裁判端保存最终NG；定位在客户端现场核验 |
| 侧面LOGO破损 | 同上，验证不能只依赖正面相机 |
| 正面LOGO脏污 | 客户端最终NG，服务端原始消息与界面一致 |
| 侧面LOGO脏污 | 客户端最终NG，不能漏发或被另一路OK覆盖 |
| 型号/标签错误 | 改变实物使之与服务端指定目标不一致，应得到NG |
| 目标切换 | BOX_A切到BOX_B后客户端确实更新检测规则，不只发送target_ack |
| 两路汇总 | 任何一路异常，客户端最终NG；服务端不替它汇总 |
| 强光/暗光 | 按评分细则的样件组合现场验证，通信记录对应实际样件 |

标签读出、缺陷位置、标签方向/位置、镜头光源参数、图像完整性仍在参赛客户端现场验收，不能由本服务端的“收到结果”代替。

## 5. 螺钉赛项实物验证

完整品连续3次正确判OK；1、2、3、4号位置各制作一个漏打样件并判NG；强光下完整品及一个漏打品分别正确输出；暗光下同样验证。四个螺钉目标必须在实际图像中完整，不用模拟客户端替代真实检测验收。

每次检测由参赛程序自动得出结果，不使用人工点击OK/NG冒充自动判断。裁判“开始本轮”只是测试控制/编号登记，不能替代参赛端视觉算法。

## 6. 通信故障注入

| 测试 | 预期观察 |
|---|---|
| 正常一次最终结果 | 只有一条正式结果，ACK表示已保存 |
| 一条报文分两次/多次发送 | 未收齐前不判定，收齐后解析一次 |
| 多条报文一次发送 | 按LF逐条解析，不粘成一条 |
| 相同ID相同结果发两次 | 一条结果，重传次数增加，第二次ACK duplicate=true |
| 相同ID更改结果 | MSG_ID_CONFLICT，原结果不变 |
| 同轮新ID再次发结果 | DUPLICATE_RESULT，原结果不变，重复证据保留 |
| 发送小写ok或NOT_OK | 拒绝，不把包含OK的任意字符串当合格 |
| 使用上一场次/不存在轮次 | 拒绝，不污染当前轮 |
| 使用错误目标版本 | 拒绝，等待计时不重置 |
| 限时内不发结果 | TIMEOUT、实际结果为空，不自动补NG |
| 超时后才发结果 | LATE，归属原轮，不完成下一轮 |
| 测试期间断线重连 | 断线证据保留、原计时不重置、原轮ID不变 |
| 取消本轮后再发 | ROUND_CLOSED，不恢复正常结果 |
| 停止监听时仍有活动轮 | 活动轮标记INTERRUPTED |
| 程序异常退出后重启 | 未完成轮标记INTERRUPTED，旧场次不自动续测 |
| 无法保存数据库 | 不返回虚假持久化ACK，界面提示冻结；应在隔离副本中测试 |

模拟器可以辅助验证：

```powershell
py -3.12 client_example.py --access-code 实际接入码 --repeat-same-id
py -3.12 client_example.py --access-code 实际接入码 --new-id-duplicate
py -3.12 client_example.py --access-code 实际接入码 --delay 5
```

最后一个示例需由裁判端设定一个小于5秒的测试时限才会出现迟到，仅用于故障注入，不是建议比赛时限。不要同时启动多个模拟客户端占用同一场次。

## 7. 连续运行和证据交接

两个赛项分别用真实相机/算法连续运行不少于10个检测节拍，交替使用合格品与不同异常品。逐轮记录实物类别、预期与实际值，人工检查客户端是否掉线、卡死、结果丢失、明显漂移，服务端是否超时、重复或错发。

界面断线计数对应“等待结果期间”的断线；轮间连接事件在审计日志中核对，不能仅凭计数为0断定全程无掉线。

至少做一次30分钟以上的现场试运行作为部署加测（这是建议验收，不是截图规定分值要求）。确认日志增长、磁盘空间、界面响应、停止/重连和导出可用。此版本当前未在交付环境完成该现场长期测试。

导出当前场次与一个历史场次，核对轮数、样件、预期、实际、耗时与日志。CSV能打开中文，JSON可解析，SHA256清单匹配；保留完整导出与软件版本。记录“测试次数”而非擅自称“生产数量”。

## v1.1 现场大屏追加验收

- [ ] 打开的是服务端的实时网页，不是标有“演示”的 `preview_display.html`。
- [ ] Windows使用扩展屏，裁判桌面、接入码、样件名称与预设答案未被镜像到观众屏。
- [ ] 参赛队伍、赛项切换后，展板统计清零并跟随新场次；旧记录仍可在裁判窗口查看。
- [ ] 实物OK、实物NG、取消、超时、迟到均可在大屏正确区分，不把超时记成NG。
- [ ] NG区域明确是参赛软件的产品判定；没有把NG数量当成错误次数或扣分数。
- [ ] 停止网页服务或断开大屏网络后，主要结果不再维持“实时OK”，而显示过期/断线提示。
- [ ] 展板数据恢复后自动更新；不出现任何未经标记的演示数据。
- [ ] 公共接口没有expected/matched/接入码/样件类别/原始日志等内容。
- [ ] 全屏、明亮/深色模式、实际大屏分辨率、Windows缩放、LED边缘裁切通过实机检查。
- [ ] 最远观众位置仍可读懂队伍、赛项、主要结果；页面时钟和记录时间符合现场时区。
- [ ] 已按现场管理要求处理电脑自动休眠/屏保/通知；程序不会自动修改这些系统设置。
- [ ] 真机长时间连续运行及多浏览器同时观看不影响TCP检测与证据保存。
